# Feature: hoop-completion

Complete Hoop end to end (core layers + every screen), replace every browser alert with modals, polish visuals, and write the system manual.
Branch: `feat/hoop-completion`. UI copy stays in Spanish (project convention from `CLAUDE.md`: "nombres semánticos en inglés para el código e interfaz en español"); code, identifiers and comments in English.

## Specs

- **S1** — "No quiero ningun ALERT, todo modales." No `alert(`, `confirm(` or `prompt(` anywhere in `src/`. Every notice, warning and confirmation is shown in an in-app modal dialog (built on `ModalSheet`), with a typed API: `notify({ title, message, tone })` and `confirm({ title, message, confirmLabel, tone }) => Promise<boolean>`.
- **S2** — "NO USES EMOJIS". No emoji characters in `src/` or in docs. Icons only from `lucide-react`.
- **S3** — "MEJORA TAMANIOS, ICONOS". Minimum readable text 12px (tokens `--text-2xs` >= 12px), consistent icon sizes via tokens/constants (16 inline, 20 nav/buttons, 24 hero), touch targets >= 48px (56px in the live console, per `CLAUDE.md`).
- **S4** — "mejora visualmente todo". Every screen polished on the "Hardwood & Neon" design system; no inline `style={...}` except dynamic values (shot-chart coordinates / GSAP). No `<button>` nested inside `<a>`.
- **S5** — "Termina todo lo que falte, frontend y backend". There is no server in this project (offline-first Zustand + localStorage by design), so "backend" = the core layers (`src/core/domain`, `application`, `infrastructure`). Concrete gaps to close:
  - S5.1 Store logic moves to pure, tested use-cases; score and team fouls are derived from events (single source of truth), so undo across quarters is correct.
  - S5.2 `+/-` uses the starting five (`startingLineupOwn`), not the current lineup.
  - S5.3 Timeouts are consumed per FIBA period (2 first half, 3 second half, 1 per OT) for own team and rival; refusal shown in a modal when none remain; the clock pauses.
  - S5.4 Game clock is persisted (saved on pause, on each recorded event, on quarter change, on leaving); events record the real clock; at 00:00 a modal offers to advance the quarter.
  - S5.5 A live match can be finished (confirm modal) and then opens its box score.
  - S5.6 Rival team fouls can be recorded (feed the rival bonus lights).
  - S5.7 Dashboard KPIs, leaders and medical alerts are computed from real data (no hardcoded numbers or injury reasons; players get an optional `medicalNote`).
  - S5.8 Box score quarter partials computed from events (including OT periods that exist).
  - S5.9 Divisions: create (also creates its team), edit, delete (confirm), view roster, assign head coach from users.
  - S5.10 Players: create, edit, delete (confirm), call up juveniles (modal feedback), medical note.
  - S5.11 Matches: create with date/time and team derived from division, edit and delete scheduled matches (confirm), sorted by date.
  - S5.12 Lineup: candidates are the match team roster plus called-up players; 5 starters exactly, max 12 in roster; once LIVE the starters are locked.
  - S5.13 Role switcher in the nav rail is the store's role (not local state); simple RBAC permission matrix in the domain hides/disables actions.
  - S5.14 Persisted store gets a version + migration so old localStorage data reseeds instead of crashing.
  - S5.15 Realistic seed: finished matches with full play-by-play (scores match the events), live match with events, so every screen shows real computed data.
  - S5.16 `/matches/live` opens the current live match or shows an empty state; live console shows a gate when the match is not live.
  - S5.17 Layout metadata: title "Hoop", `lang="es"`, Geist fonts wired into tokens.
- **S6** — "UTILIZA PRINCIPIOS DRY, KISS, YAGNI, CLEAN CODE, CLEAN ARCHITECTURE". Domain rules pure and framework-free; use-cases in `application`; shared UI primitives instead of duplicated markup (form fields, filter chips, page header, empty state, link buttons); delete empty `export {}` barrels that nothing uses; no `any`.
- **S7** — "HAZ UN MANUAL DEL SISTEMA". `docs/MANUAL.md` (Spanish, user + technical: roles, every screen and flow, FIBA rules applied, architecture, scripts) and a real `README.md` pointing to it.
- **S9** — "modifica toda la estetica de este sitio para que use la combinacion/combinaciones/paleta de colores del club atletico monte grande. Mejora las fuentes tambien totalmente, hazlas modernas, y todo el front en general, si quieres usa alguna skill, agrega animaciones con gsap... Termina con lo otro primero y luego haz esto..." - **S10** — "Deberiamos tener una mezcla de los dos, osea, que el proyecto tenga servidor y base de datos. Que guarde todo en el navegador pero tambien vaya al back, si hay algo nuevo lo pise, y si no hay internet que lo guarde en el navegador y cuando haya lo mande... Me explico? Hagamos esto". Local-first with sync: every write lands in the browser first and in a persistent outbox; the outbox is flushed to the server when online and retried when connectivity returns; pulls merge server changes with last-write-wins by `updatedAt` for divisions, teams, players and match metadata; play-by-play events merge append-only by event ID (never overwritten). Decisions (L10): PostgreSQL (Docker for dev), real email + password login with hashed passwords and secure cookie sessions, roles enforced server-side, live push to other devices via Server-Sent Events.
  - S10.1 Infra: `docker-compose.yml` with `postgres:17-alpine` (db `hoop`, user/password from env, named volume); `.env.example` with `DATABASE_URL` (and documented defaults); real `.env*` stays gitignored. Drizzle ORM + `pg` for access, `drizzle-kit` for versioned SQL migrations committed under `drizzle/`. Server code lives in `src/server/**` (marked `import 'server-only'`), never imported by client components.
  - S10.2 Schema: `users` (id, email unique lowercase, name, role, password_hash, created_at, updated_at); `sessions` (id = SHA-256 of the random token, user_id FK cascade, expires_at, created_at); `sync_records` (kind in division|team|player|match, id, data jsonb validated with the domain zod schemas, updated_at timestamptz = client change time used for LWW, deleted boolean tombstone, seq bigint from a global sequence bumped on every accepted write, PK (kind,id)); `match_events` (id PK, match_id, data jsonb validated with PlayByPlayEventSchema, deleted boolean tombstone, seq from the same global sequence). Match records never embed events (events travel only through `match_events`).
  - S10.3 Auth: passwords hashed with Node `crypto.scrypt` (random 16-byte salt, constant-time compare, encoded `scrypt$N$r$p$salt$hash`); login creates a 32-byte random token, stores only its hash, sets cookie `hoop_session` (httpOnly, sameSite lax, secure in production, path /, 30 days); logout deletes the session and clears the cookie; `GET /api/auth/me` returns the user without password data. Generic error message on bad credentials ("Email o contraseña incorrectos"), no user enumeration. Route handlers under `src/app/api/auth/{login,logout,me}`.
  - S10.4 Server-side RBAC reuses `can()` from the domain: division/team writes need MANAGE_DIVISIONS; player writes need MANAGE_PLAYERS; match create/delete need MANAGE_MATCHES; match updates need any of MANAGE_MATCHES, MANAGE_LINEUP, RECORD_LIVE; event writes need RECORD_LIVE. Unauthenticated -> 401, forbidden -> 403 per rejected item.
  - S10.5 Seed: `npm run db:seed` loads `createSeedState(now)` from the shared core into `sync_records`/`match_events` and creates the seed users with a demo password taken from `SEED_DEMO_PASSWORD` (documented default `camg1922`); idempotent.
  - S10.6 Sync API: `POST /api/sync/push` body `{ records: [{kind,id,data,updatedAt,deleted}], events: [{id,matchId,data,deleted}] }` applies LWW per record (accept only when incoming updatedAt > stored updatedAt; ties keep the server row) and append-only events (insert if new; a deletion tombstone always wins and is never undone); responds `{ accepted: ids, rejected: [{id, reason}], cursor }`. `GET /api/sync/pull?since=<seq>` returns everything with seq > since (records + events, including tombstones) and the new cursor. `GET /api/sync/stream` is an SSE endpoint (authenticated) that emits `event: changed` with the latest cursor whenever any write is accepted (Postgres LISTEN/NOTIFY so it works across server instances) plus a heartbeat every 25 s.
  - S10.7 Client sync engine: a sync module subscribes to the club store and detects changed/removed entities and new/removed events by immutable-reference diff, stamps `updatedAt`, and enqueues them in a persisted outbox (localStorage, survives reloads). It flushes when online (`navigator.onLine` + `online` event + retry with exponential backoff capped at 60 s), pulls on start, on SSE `changed` and after reconnect, and merges pulled data into the store with the same rules (LWW for records, append-only + tombstones for events, then re-derive scoreboards). Applying pulled data must not re-enqueue it. Offline the app keeps working exactly as today.
  - S10.8 Client auth: `/login` screen (email + password, CAMG branded, modal errors), the authenticated user replaces the simulated role switcher (role comes from the server); the last user profile is cached so the app opens offline; logout clears session and outbox only after a successful flush (or asks via `confirm` when unsynced changes remain). A visible sync status indicator in the shell: Sincronizado / Sincronizando / Sin conexión (N pendientes) / Error.
- **S11** — "Hiciste un manual del sistema dentro del mismo sistema como te pedi?" In-app help screen `/ayuda` rendered from `docs/MANUAL.md` (single source, DRY) with a table of contents, CAMG styling, reachable from the nav and the user menu, available offline once loaded.
- **S12** — "Tambien quiero tipo esas pantallas de inicio que dejan todo grisado y te van mostrando con un ejemplo el uso del sistema como walktrhough la primera vez que te logueas/inicias sesion? Tipo con flechitas y textos/notas auxiliares?" Guided tour: dimmed overlay with a spotlight on the target element, tooltip card with an arrow, step text and example, Siguiente / Atras / Saltar, progress, keyboard (Enter, arrows, Escape), GSAP motion with reduced-motion fallback, responsive. A welcome tour on the first login of each user, a mini tour the first time each main screen is visited (dashboard, divisiones, jugadores, partidos, quinteto, consola en vivo, planilla), steps filtered by the user's role, seen state persisted per user, and "Ver tutorial" to replay from Ayuda and the user menu.
- **S13** — "Estas limitaciones podemos resolverlas tambien?" Resolve the five known limitations:
  - S13.1 Concurrent edits of one match from two devices merge per field (field-level LWW for match records on client and server); events stay append-only.
  - S13.2 The server rejects events whose match does not exist (neither stored nor in the same push batch) with reason INVALID.
  - S13.3 Only one browser tab runs the sync engine (Web Locks leader election); other tabs follow the persisted state (storage events) and take over if the leader closes.
  - S13.4 The live console shows the sync status indicator.
  - S13.5 FIBA halftime: when Q2 ends the match goes to HALFTIME (console shows Entretiempo and lets you start Q3); FIBA rule of at most 2 second-half timeouts in the last 2 minutes of Q4 is enforced.
- **S8** — Quality gates: `npx tsc --noEmit`, `npm run lint`, `npm test`, `npm run build` all pass.
